## 1. Кратко: что изменилось для пользователя

За десять дней продукт закрыл корпоративный цикл расчётов, привёл факт трудоёмкости к регистру привязки «группа ИИС с даты» и одновременно укрепил инфраструктуру: единая авторизация, журнал действий, журнал схем БД, кэш React Query.

Главное, что видно в интерфейсе:

- Справочник трудоёмкости: история привязки к группе ИИС по датам; факт берёт группу на дату версии, а не слепок импорта.
- Часы факта остаются на заявленном узле (и его незаявленных потомках), а не всегда схлопываются на первый уровень IIC.
- Вкладка **Администрирование → Ресурсы**: графики CPU/RAM/SQL/Redis и история до 90 суток.
- Нормы IIC: тип **«Логнормальное распределение»** (раньше «Кривая Кима»); справочник **«Стоимость работ»** уже даёт ₽ на титуле PDF прогноза.
- Написание **БЕР** вместо «БЭР»; шкала Z на визуальных отчётах слева хуже, справа лучше.
- Двойной щелчок в редакторах справочников открывает карточку записи.
- После создания, копирования и архивации версии гриды прогноза, факта и сравнения обновляются без «залипшего» кэша.
- Вкладка «Комплекты документации» скрыта в навигации справочников.

Что изменилось «под капотом», но влияет на корректность:

- Одна основная неархивная версия на проект и направление.
- Журнал действий пишет мутации версий, данных, импорта и пользователей.
- Формулы Z, перерасхода часов и среднего тренда только в `PerformanceCalculationEngine`.
- Импорт Excel разобран на отдельные сервисы; поведение Replace не менялось.

## 2. Факт трудоёмкости и привязка к группам IIC

Это главная бизнес-доработка конца периода (7–9 сентября).

### 2.1. Свёртка часов на первый уровень (7 сентября)

Таблицы вкладки **Отчет** (топ-5, «Все группы физобъёмов IIC», дерево на корнях, PDF сводных, «Сводный вер 2») показывали группы IIC первого уровня, но часы типа документа (TF) жили на листьях и отфильтровывались в «—».

Исправление: часы факта поднимаются на IIC первого уровня (`RollHoursToFirstLevel`), объём берётся с поддерева (`SubtreePhysicalVolume`). **Анализ факта и норм** и симулятор «Анализа норм» берут точки с корней: X = объём поддерева, Y = производительность. Фильтр по потомку поднимается на L1. Кэш FactNorm: `fact-norm:v2`.

Импорт TF сопоставляет тип документа со справочником по `DocumentTypeName` **или** `Name`. Отсутствующие типы UI добавляет в справочник по умолчанию.

Excel/PDF **Факт → Итого** по-прежнему печатает собственные `FactLaborHours` на всех уровнях дерева — это отдельный путь от таблиц отчёта.

### 2.2. Регистр «группа ИИС с даты» (9 сентября)

Справочник трудоёмкости получил периоды привязки `LaborIntensityIicBindings` (схема `123`). Двойной щелчок по строке открывает историю: добавить, править, удалить период.

Факт больше не берёт группу из слепка импорта (`ProjectLaborIntensities.WorkDirectionId` как единственный источник). Группа строки факта — из регистра **as-of даты версии** (`CreatedAt`). Пустой регистр не отключает старую свёртку на L1.

Выгрузка Excel справочника трудоёмкости включает все уровни дерева. Вкладка «Комплекты документации» скрыта в навигации.

### 2.3. Заявленные узлы вместо только L1 (9 сентября)

Если на дату версии в регистре есть заявленные узлы, часы **не** поднимаются все на L1.

Правило:

- заявленный узел собирает себя и потомков;
- ветвь, заявленная отдельно, в родителя не входит;
- объём — у ближайшего заявленного предка;
- производительность узла с часами = `hours / объём этой корзины`;
- отчёт, PDF, тренды и точки факт/норма показывают узлы с собственными факт-часами, не только первый уровень;
- пустой claimed-set по-прежнему делает `RollHoursToFirstLevel`.

На «По объектам / Детально» оценка факта сначала режет точное `(DocSet, ClassifierId)`, иначе бакет ближайшего заявленного узла (или L1, если claimed пуст). «(пусто)» только у строк трудоёмкости без направления.

Каталожный refresh групп IIC из Excel (`025` / `026`) остаётся скриптом данных, не источником истины факта в рантайме. На живой БД повторный db-init не гоняет 025/026, пока не задано `FORCE_NOMENCLATURE_REFRESH=1`.

## 3. Корпоративный цикл расчётов и справочников (31 августа — 1 сентября)

Коммит `d4b771b` (1 сентября) довёл цикл, начатый 31 августа.

### 3.1. Смешанный объём группы `V_g`

Оборудование входит в тот же `V_g`, что и физические объёмы: при группировке по проекту/объекту норма `N` считается от суммы assessed-объёмов ФО и оборудования одной группы ИИС. Пустой `FacilityCode` у оборудования — отдельная корзина, не смешивается с объектами. Оценка «Нет» в `V_g` не входит.

Кривая логнормали: `N` не зависит от V, поэтому mixed и per-item численно совпадают; группировка обязательна для Wright и прочих `N(V)`.

Существующие часы сами не обновляются. После выкладки нужен **Пересчитать** или `scripts/recalculate-all-labor.sh` для всех неархивных версий.

### 3.2. Плановые объёмы и комплекты документации

Sibling-PPV больше не обнуляются при сохранении объёма группы. В сценарии «каждая позиция» несколько строк ФО по направлению — ошибка 400. В групповых сценариях V* распределяется пропорционально физобъёму.

Распределение трудоёмкости факта — по сущности DocSet (`DocSetId`), не парсингом `|` из `DocumentationCode`. Импорт трудоёмкости выделяет код после `|`; unmatched — карантин (часы не в распределении).

### 3.3. Подписи, лимиты, журнал пересчёта

- Гриды и факт: **«Оценка Z»**.
- План в отчёте: **«Заложенный Z»** (параметр планирования, не live-оценка грида).
- Лимит Excel **10 МБ** (nginx и API).
- Конкурирующее сохранение версии анализа — **409**.
- Журнал пересчёта версии: `GET /api/projects/{id}/versions/{vid}/calculation-log`.

### 3.4. Формула «Логнормальное распределение»

Тип формулы норм IIC `KimCurve` (`FormulaType.KimCurve = 12`, код API `KIMCURVE`) в справочнике, редакторе, анализе норм и сообщениях валидации называется **«Логнормальное распределение»**.

Смысл: `P(z) = e^(μ + z·σ)`, `μ = ln(P)`, σ в лог-пространстве. Часы плана `LI(z) = P(z)·V`; при z = 0 совпадает с постоянной нормой. В регистр пишутся `Estimate = μ` и `StandardDeviation = σ`. Массовый пересчёт существующих норм и снимков версий не делался.

Редактор, грид, карточка анализа норм и выгрузка реестра показывают производительность, μ и σ отдельными подписями. FactNorm не предлагает этот тип в BIC-каталоге; для текущей логнормальной нормы σ факта считается как `std(ln(Y))`.

### 3.5. Стоимость работ и написание БЕР

Справочник **«Стоимость работ»** (ставка ₽/ч по дереву групп IIC, версионность датой) уже был до этого окна; в этот период на титуле PDF прогноза под каждым сценарием выводится стоимость: ставка as-of `CreatedAt` версии × часы. Контентные страницы без ₽. Уникальный индекс ставки досоздан скриптом `122`.

Во всём приложении, сообщениях API, сидах и документации «БЭР» заменено на **БЕР** (миграция `114`).

### 3.6. Шкала Z и двойной щелчок

На визуальных шкалах Z (сводный вер 1 и вер 2, PDF-отчёт) слева хуже (`+3` / Критично), справа лучше (`−3` / Отлично). Числа в таблицах и оси графиков не менялись.

В модалке «Редактирование нормы» двойной щелчок по строке периода открывает карточку записи. То же для диалога выбора проекта и справочника «Стоимость работ».

## 5. Единый движок расчётов (7–8 сентября)

Вся математика остаётся в `PerformanceCalculationEngine`. За эти дни убраны обходные формулы.

- Взвешенный Z `Σ(Z×вес)/Σ(вес)` — только `ComputeWeightedZ`. Сравнение версий, сводка детального факта и тренд Z больше не считают это сами. `WeightedZAggregator` и `WeightedZScoreCalculator` — внутренние примитивы движка.
- Калькулятор отклонения внедряется из движка; переход estimate → производительность (`e^estimate`) — метод `EstimateToProductivity`. FactNorm не вызывает `Math.Exp` напрямую.
- Перерасход часов в PDF-инсайтах — `ComputeHoursOverrun`.
- Взвешенное среднее тренда по месяцам — `WeightedZAggregator.Mean` без округления.

Движок и билдер гридов разобраны на partial-файлы по областям (Fact / Forecast / Hours / Performance / Trend и Fact / Forecast / Compare) без смены формул. Неиспользуемые члены интерфейсов сервисов удалены.

## 6. Авторизация, основная версия, журнал действий (7–8 сентября)

### 6.1. Единый `[HasPermission]`

API: вместо `[Authorize(Roles=…)]` и ручных `IsAdministrator()` / `Forbid` — `[HasPermission]`.

- Матрица прав и access-rights: `GET` — `Administration:Read`, `PUT` — `Administration:Edit`.
- `PUT /api/system-settings` — `Administration:Edit` (классовый `[Authorize(Roles="SuperAdmin,Administrator")]` снят).
- `GET /api/system-settings` остаётся `[Authorize]` (heartbeat).
- Шаблоны формул норм — `IicWorkDirectionNorms:Read`.
- `GET /metrics` — аутентификация **и** `Administration:Read`.

Глобальная `FallbackPolicy` = `RequireAuthenticatedUser`: любой endpoint без атрибутов требует вход; аноним только с `[AllowAnonymous]`. Guard-тест покрывает контроллеры рефлексией. Объект **Администрирование** есть в матрице клиента.

### 6.2. Одна основная версия

Filtered unique index `UX_ProjectAnalysisVersions_OnePrimary`: одна основная неархивная версия на проект и направление. Дубликаты понижаются, остаётся новейший `Id`. Смена основной (создание, «Сделать основной», смена направления) — два `SaveChanges` в транзакции. Архивация основной и назначение новой основной — одна транзакция: направление не остаётся без primary при сбое.

### 6.3. Журнал действий

`IUserActionLogger` пишет мутации версий, данных версии, импорта, норм, стоимости, пользователей, справочников и настроек. Запись после `SaveChanges` / commit, через отдельный `DbContext`: сбой журнала не откатывает бизнес-операцию. Guard-тесты проверяют строку журнала после создания версии и ФО.

## 7. База и nginx (8 сентября)

### 7.1. Журнал схем `dbo.SchemaMigrations`

`docker-db-init.sh` обходит `migrations/schema/*.sql` в C-locale и штампует журнал. Checksum — SHA-256 файла на момент штампа. Применённый скрипт с другим хешем роняет init: правки только новым номером, не правкой уже применённого файла.

Baseline `001–016` на существующей БД штампуется только по свидетельству (таблица / колонка / длина). Если свидетельства нет, скрипт выполняется, а не пропускается (раньше `UserSettings` могла потеряться навсегда).

`122` досоздаёт уникальный индекс стоимости работ, если `115` успел создать только таблицу.

### 7.2. Nginx — один шаблон

Единый конфиг: `client/nginx.conf.template`. `envsubst` подставляет только `PROXY_TRUSTED_SECRET`. Заголовок `X-Trusted-Proxy-Token` уходит в `/api/`. Корневые `nginx.conf*` удалены. SPNEGO — `client/nginx/spnego.inc.example` и overlay `docker-compose.spnego.yml` на том же образе frontend. HSTS через `x-forwarded-proto`, `X-Remote-User` через `map $remote_user`.

## 9. Клиент: React Query, кэш, разбор экранов (8 сентября)

### 9.1. React Query

Аналитика, справочники, нормы IIC, стоимость работ, отчёты и параметры планирования переведены на `useQuery` / `useMutation`. Фабрика `queryKeys`. Ручные `AbortController` и debounce убраны.

Панели проекта (прогноз, факт, сравнение) — `useQuery` с ленивой детализацией. Тулбары и хуки выгрузки вынесены отдельно. Общее контекстное меню детализации: `useProjectDetailContextMenu`.

Справочники грузятся через `useDictionaries` (один `GET /api/dictionaries/all` на приложение). `useDictionaryStore` остаётся lookup-слоем без собственного fetch.

### 9.2. Инвалидация кэша

После создания, копирования, архивации и «сделать основной» инвалидируются `projectVersions`, `fact`, `forecast`, `compare` данного проекта. После создания или правки проекта — `projects.all`. После правки норм IIC и норм факта — `analytics.root` и `dictionaries.all`.

`ProjectTrendPanel` и `HoursTrendPanel` — `useQuery` с `signal`.

### 9.3. Разбор крупных экранов

Контейнеры ≤280 строк плюс тулбар / грид / диалоги / хуки данных:

- `ProjectVersionPickerDialog` + `useVersionPickerActions`
- `IicNormsPage` + `useIicNormMutations`
- `PlanningParametersDialog` + `usePlanningQueries`
- `ProductivityTrendPanel` + `useProductivityTrendData`
- `FullProjectsPage`

DOM, `data-testid` и права (`usePermission`) без изменений.

### 9.4. Качество клиента

- Типизированные объекты прав `PermissionObjectName`.
- Подсказки ошибок API для 410 и 413.
- `ErrorBoundary` вокруг `Outlet` со сбросом по `pathname`.
- Стабильные пустые строки грида и `memo(DataTable)`.
- ESLint 9, Prettier, скрипты `typecheck` / `lint:eslint`, бюджет бандла в сборке.

## 11. Незакоммиченная рабочая копия (9 сентября)

На момент составления обзора в дереве есть незавершённый разбор панелей проекта и чистка устаревших методов движка. Это ещё не в git.

Клиент: гриды и диалоги факта, прогноза и сравнения вынесены из панелей в отдельные файлы (`FactDetailGrid`, `FactFacilityGrid`, `ForecastDetailGrid`, `CompareSummaryGrid` и хуки `useFactVersion`, `useForecastPlanVersion`, `useCompareVersions`). Поведение экранов при этом не менялось намеренно — это продолжение декомпозиции 8 сентября.

Движок: из публичного интерфейса убраны методы, которые считали прогнозные часы **без** оборудования в `V_g` (`ComputeForecastBaseHours`, `RecalculateLaborIntensities`, `ComputePpvForecastHours`, `AggregateForecastHoursByDirection`, `ComputeEquipmentForecastHours`). Остаётся совместный пересчёт `RecalculatePlanHours` (ФО и оборудование в одном `V_g`). Вызовы в отчёте, page-data и билдере гридов переведены на оставшийся путь.
