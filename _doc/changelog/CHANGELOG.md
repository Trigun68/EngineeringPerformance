### Added (2026-08-27, две поверхности «Тренд»)
- **Проект → Отчет → «Тренд»:** третья подвкладка рядом со сводными. Срез — основная факт-версия проекта (+ основная план для моста часов); история — все неархивные версии проекта. Блоки: чипы версии, динамика Z по датам, мост часов по корневым группам IIC (эффект объёма и эффект производительности), столбцы Z от 0 по группам IIC, S-curve часов факта; водопад ΔZ за период — в «Дополнительно». API `GET /api/projects/{id}/report-trend` (право `Reports`).
- **Аналитика → «Тренд оценки»:** первый экран — четыре блока портфеля (Z по датам, мост часов, сетка Z от 0 на группу IIC с осью «проекты», S-curve портфеля). KPI «было/стало» и таблица версий с первого экрана убраны. ΔZ и нормативные сегменты — в «Дополнительно». «Тренд оценки производительности» не менялся.
- **Мост часов** считается только в `PerformanceCalculationEngine.ComputeHoursBridge`: `hoursAtPlanRate = H_plan × (V_fact / V_plan)`, `volumeEffect + productivityEffect = H_fact − H_plan`. Портфель суммирует мосты проектов (`CombineHoursBridges`). Клиент формулу не дублирует.

### Investigated (2026-05-11, ISS-006 — импорт LI теряет ~2 830 ч из-за truncate + overwrite)
- Диагностика реального файла `.src/25-310 Трудоемкость прокта.xlsx` (Факт v2, проект 4) подтвердила расхождение «файл vs БД»: 1 008 строк в файле, 0 дублей по `(DocType, Brand)`, **сумма planned 61 725.40 ч**. В БД (`ProjectLaborIntensities` за `ProjectId=4, ProjectAnalysisVersionId=2`) — **860 строк, 58 895.24 ч**.
- Корневая причина — двойная. (1) `EngineeringPerformance.Infrastructure/Services/DataImportService.cs:536-539` обрезает `DocumentationCode = "<DocType>|<Brand>"` до 100 символов перед записью; 267 строк файла имеют длину >100, многие после truncate коллизионно совпадают. (2) `DataImportService.cs:568` затирает дубли по `(DocumentationCode, WorkDirectionId)` присваиванием (`mergedByNaturalKey[...] = entity`) вместо суммирования `PlannedHours`/`ActualHours`. Топ-потери: `VS_04 Определение количества и типа приборов…` (22 строки, потеря 344 ч), `HS_02 Тепловой расчет помещений…` (22 строки, 192 ч), `IE_02 Общие принципы защиты…` (15 строк, 164 ч) — это разные объекты с одинаковой маркой документа, неотличимые после truncate.
- Решение согласовано (truncate + суммирование): расширить `DocumentationCode` до `nvarchar(450)` миграцией EF + поднять лимит truncate в импортёре, на коллизии суммировать часы. План и промт для продолжения — `tmp/ISS-006-handoff.md`. Issue-карточка ISS-006 будет заведена в следующей сессии.

Реализовано как пробный образец перед применением паттерна к остальным карточкам справочников.
