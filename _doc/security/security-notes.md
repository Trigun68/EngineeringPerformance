# Заметки по безопасности (аудит 2026-05-13)

Дата: 2026-05-13. Источник: обзор кода App / Infrastructure / Core и точечные правки в той же итерации.

## Аутентификация и данные учётных записей

- Пароли хранятся как **BCrypt**-хеши (`User.PasswordHash`); проверка — `BCrypt.Verify`.
- Ответ при неверном логине/пароле унифицирован (**Invalid credentials**), чтобы не облегчать перечисление учётных записей по разному тексту ошибки.
- Запись в журнал действий при неверном пароле: текст без имени пользователя (`Invalid password`), идентификатор пользователя в БД журнала сохраняется для расследований.

## Строки подключения

- Файл настроек: `%APPDATA%\EngineeringPerformance\settings.json` (см. `AppSettings`). Доступ ограничен профилем Windows; строка может содержать пароль SQL-аутентификации — **не** логировать целиком в Serilog/консоль.
- Утилита `ConnectionStringMasking.MaskForDisplay` — для безопасного вывода (диагностика, консольные утилиты).

## SQL и импорт

- Пользовательские строки в запросах идут через **EF Core** / параметризованные API; по коду не найдено `FromSqlRaw` / конкатенации SQL с вводом пользователя.

## Сидирование и демо-учётные записи

- `DatabaseSeeder` при пустой таблице `Users` создаёт учётные записи с **известными паролями по умолчанию** (см. код сидера). В эксплуатации пароли необходимо **сменить после первого входа**; не использовать эту БД как продакшен без смены секретов.

## Кеш и консистентность

- Процессный кеш дерева ИИС в `PerformanceService` сбрасывается при любой мутации `IDirectoryCache<IicWorkDirection>` (декоратор в DI), чтобы метрики не расходились с справочником в длинной сессии.

## Рекомендации на будущее

- Зафиксировать **LTS SDK** в `global.json` для CI (сейчас возможен preview .NET 10).
- Рассмотреть политику блокировки учётной записи после N неудачных попыток входа (сейчас не реализовано).
