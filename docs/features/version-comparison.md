## Описание

Функция сравнения версий анализа позволяет сопоставить данные двух версий проекта (оценка производительности, физические объёмы, трудоёмкость) и выявить различия между ними.

## Структура вкладки «Сравнение версий»

Вкладка содержит три подвкладки:

### 1. Итого
Иерархическое дерево направлений ИИС с агрегированными показателями:

| Столбец | Содержание |
|---------|------------|
| Направление | дерево групп IIC |
| Физобъём — A / B | фактический физ. объём версии |
| Плановая трудоёмкость — A / B | BaseHours базового сценария планирования |
| Плановая производительность — A / B | BaseHours / ФО |
| Фактическая производительность — A / B | факт. производительность |
| Плановая оценка A / B | ZBase из параметров планирования |
| Фактическая оценка A / B | Z-score факта (`CalculatePerformance`) |
| Дельта Z-score — план | PlanZB − PlanZA |
| Дельта Z-score — факт | FactZB − FactZA |

**Ключ объединения:** `WorkDirectionId`

### 2. По объектам
Сравнение данных по физическим объектам (FacilityCode):
- **Код / Наименование** — идентификация объекта
- **Часы А / Часы Б** — трудоёмкость факта по версиям
- **Δ Часы** — разница трудоёмкости (B − A)
- **Z-score А / Z-score Б** — производительность по версиям
- **Δ Z-score** — разница производительности
- **Оценка А / Оценка Б** — интерпретация производительности

**Ключ объединения:** `FacilityCode`

### 3. Детально
Детальное сравнение по каждой строке физических объёмов (PPV):
- **Ключ объединения:** `(FacilityCode, DocumentSet, PvCode, WorkId)`
- **Количество А / Б / Δ** — физический объём по версиям и разница
- **Часы А / Б / Δ** — трудоёмкость факта по версиям и разница
- **Произв. А / Б / Δ** — производительность по версиям и разница
- **Присутствие** — статус строки: «A+B» (есть в обеих версиях), «только A», «только B»

## Чек-бокс «Показывать различия»

### Назначение
Фильтрует строки, скрывая записи с идентичными значениями. Позволяет сосредоточиться только на изменениях между версиями.

### Правила идентичности

#### Подвкладка «Итого»
Строка считается **идентичной**, если выполнены **все** условия:
- `Round(FactZScoreA, 4) == Round(FactZScoreB, 4)`
- `Round(PlanZScoreA, 4) == Round(PlanZScoreB, 4)`
- `Round(PlannedLaborHoursA, 2) == Round(PlannedLaborHoursB, 2)`

**Особенность TreeList:** родительские узлы скрываются **только если** все их потомки скрыты. Это предотвращает разрыв иерархии.

#### Подвкладка «По объектам»
Строка считается **идентичной**, если выполнены **оба** условия:
- `Round(HoursA, 2) == Round(HoursB, 2)`
- `Round(ZScoreA, 4) == Round(ZScoreB, 4)`

Если оба значения `null` — строка также считается идентичной и скрывается.

#### Подвкладка «Детально»
Строка считается **идентичной**, если выполнены **все три** условия:
- `Round(QuantityA, 4) == Round(QuantityB, 4)`
- `Round(HoursA, 2) == Round(HoursB, 2)`
- `Round(ProductivityA, 4) == Round(ProductivityB, 4)`

**Исключение:** строки с `Presence != "A+B"` (отсутствие в одной из версий) **всегда показываются**, так как отсутствие само по себе является отклонением.

### Округление значений

| Метрика | Знаков после запятой | Обоснование |
|---------|---------------------|-------------|
| Часы (трудоёмкость) | 2 | Стандартная точность для учёта рабочего времени |
| Z-score | 4 | Статистичетрика, требует высокой точности |
| Производительность | 4 | Расчётная величина, требует высокой точности |
| Количество (физ. объём) | 4 | Может содержать дробные значения (м², м³, т и т.д.) |

## Логика загрузки данных

### Последовательность операций

1. **Выбор версий:** пользователь выбирает «Версию А» и «Версию Б» через диалоги выбора версий
2. **Загрузка данных «Итого»:** вызов `IPerformanceService.GetPerformanceDataAsync` для обеих версий
3. **Загрузка данных «По объектам» и «Детально»:**
   - Для каждой версии вызывается `LoadFactDataForCompareAsync(projectId, versionId)`
   - Метод загружает физические объёмы (PPV), трудоёмкость (LI), нормы производительности
   - Вызывается `ComputeFactRows` — общая логика расчёта с вкладкой «Оценка факта»
4. **Объединение данных:**
   - `BuildCompareFacilityRows` — merge по `FacilityCode`
   - `BuildCompareDetailRows` — merge по `(FacilityCode, DocumentSet, PvCode, WorkId)`
5. **Применение фильтра:** если чек-бокс включён, вызывается `ApplyCompareFilter`

### Обработка строк без пары

Если строка присутствует только в одной версии:
- Поля версии A заполняются, поля версии B = `null` (или наоборот)
- Δ-колонки = `null` (невозможно вычислить разницу)
- Колонка «Присутствие» = «только A» или «только B»
- При включённом фильтре «Показывать различия» такие строки **всегда видимы**

### Параллельные DbContext

⚠️ **Важно:** загрузка данных двух версий выполняется **последовательно**, а не параллельно (`Task.WhenAll`). Это требование архитектуры приложения для корректной работы с `IDbContextFactory`.

## Производительность

### Ожидаемое время загрузки
- **Проект 4, версии v2/v3** (~12 000 PPV, ~3 000 LI на версию): < 2 сек
- **Крупные проекты** (>20 000 PPV): 3–5 сек

### Оптимизация
- Используется `AsNoTracking()` для всех запросов к БД
- Данные загружаются один раз при выборе версий, повторная загрузка не требуется при переключении подвкладок
- Фильтрация выполняется в памяти (LINQ to Objects), без обращения к БД

## Примеры использования

### Сценарий 1: Сравнение плановой и фактической версий
1. Открыть проект 4
2. Выбрать «Версия А» = v1 (план), «Версия Б» = v2 (факт)
3. Включить «Показывать различия»
4. На подвкладке «По объектам» увидеть объекты, где фактическая трудоёмкость отличается от плановой
5. На подвкладке «Детально» увидеть конкретные строки PPV с отклонениями

### Сценарий 2: Анализ изменений между итерациями
1. Выбрать «Версия А» = v2 (итерация 1), «Версия Б» = v3 (итерация 2)
2. Отключить «Показывать различия» — увидеть полную картину
3. Включить «Показывать различия» — сосредоточиться на изменениях
4. Экспортировать данные в Excel (будущая функция) для отчёта

### Сценарий 3: Поиск новых/удалённых объектов
1. Выбрать две версии для сравнения
2. Включить «Показывать различия»
3. На подвкладке «Детально» отфильтровать по колонке «Присутствие»:
   - «только A» — объекты, удалённые во второй версии
   - «только B» — объекты, добавленные во второй версии

## Ограничения и известные особенности

1. **Сравнение только факта:** функция работает с данными факта (PPV + LI). Сравнение прогнозных данных не поддерживается.
2. **Последовательная загрузка:** данные двух версий загружаются последовательно, что может увеличить время ожидания на крупных проектах.
3. **TreeList «Итого»:** при включённом фильтре родитекие узлы остаются видимыми, если хотя бы один потомок имеет отличия. Это может создать впечатление, что родительский узел тоже изменился, хотя на самом деле изменились только потомки.
4. **Дубликаты по ключу:** если в одной версии несколько PPV имеют одинаковый ключ `(FacilityCode, DocumentSet, PvCode, WorkId)`, они суммируются перед merge. Это корректное поведение, но может быть неочевидным для пользователя.
